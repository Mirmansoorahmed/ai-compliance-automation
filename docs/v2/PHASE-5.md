# Phase 5 — wider detection

> Northwind Advisory for Halvaro Payments GmbH (fictional). Phase 5 widens the legal coverage of the detection data. Synthetic data only; not legal advice, not a conformity claim.

## What Phase 5 adds

Until now the Semantic Guard had curated exemplars and legal elements for **Art. 5(1)(c)** (social scoring) only. Phase 5 adds exemplar files — positives + hard negatives in German and English, each positive annotated with the legal elements it meets — for the concepts most relevant to a fintech:

- **Remaining Art. 5 prohibitions:** 5(1)(a) subliminal/manipulative, 5(1)(b) exploiting vulnerabilities, 5(1)(d) crime prediction from profiling, 5(1)(f) emotion recognition at work/education, 5(1)(g) biometric categorisation of sensitive traits.
- **Annex III high-risk areas:** 4(a) recruitment/selection, 4(b) employment decisions and performance monitoring, 5(b) creditworthiness, 5(c) life/health insurance pricing, 1(c) emotion recognition outside work/education.
- **GDPR intents:** Art. 9 special-category data, Art. 22 solely-automated significant decisions.

Each file (`exemplars/<concept>.json`) carries the concept's `elements` (the legal-element rubric), positives that meet every element, and hard negatives — lawful look-alikes — that meet none. The hard negatives are chosen to be the realistic confusions (fraud scoring vs credit scoring; a human-in-the-loop lending decision vs a solely-automated one; operational metrics vs emotion inference).

A **held-out set** (`eval/heldout_v2/`) holds labelled cases for these concepts that are **not** used as exemplars — **at least 6 positives and 6 hard negatives per concept, DE and EN mixed** (generated by `eval/generate_heldout_v2.py`). A committed test (`tests/test_heldout_disjoint.py`) fails if any held-out text also appears in an exemplar or tuning file, so recall is never a fit to the training texts. The official runner (`aca.eval.runner`) now builds the adapter with **all 13 concepts** and reports the tuning set per concept and the held-out set per concept, each separately.

## How detection uses this

The exemplars plug into the existing Guard loader (`aca.guard.stages.exemplars.load_concept`): stage 1 embeds the text and scores it against each concept's positives and hard negatives on the legal-element rubric. Adding a concept is a data change — no new detector code. The decision layer (`/v1/check`, OPA) already maps these concept ids to their catalog decisions (Art. 5 → BLOCK, Annex III → WARN, GDPR Art. 9/22 → ASK).

## Run the smoke check

```bash
make check-detection-demo        # or: scripts/demo_detection.sh
```

This runs a per-concept **leave-one-out nearest-exemplar separation** and writes a result JSON to `eval/results/`. It labels the output by the embedder actually used: with the **offline hashed embedder** it is a **data sanity signal only** (`smoke, not a real result`), and with the trained MiniLM model it is labelled as a model separation signal (still a data-quality check, not a held-out recall number). The hashed embedder scores on character n-grams, so some concepts separate poorly under it; that is expected and is exactly why the real number must come from the trained model.

## To be run by the owner (real eval)

The real recall / precision numbers require the trained multilingual MiniLM model and are run by the owner on a machine with the `embeddings` extra installed:

```bash
pip install -e ".[embeddings]"
make eval                 # scores the AIA-5-1-c tuning + held-out sets with MiniLM
```

- Per-concept held-out scoring for the new concepts, and the eval table in the README, are **to be measured** on that run. This repo does not invent those numbers.
- The committed `eval/results/latest.json` is from the earlier Art. 5(1)(c) run; it is unchanged by Phase 5.

## Limits

- **The smoke number is not a model metric.** Treat `loo_accuracy(smoke)` as a loader/data check, not recall.
- **Coverage is breadth, not depth.** Each new concept has a small, high-signal exemplar set (a few positives + hard negatives per language), enough to wire detection and to seed the held-out set — not a tuned corpus. Expanding and tuning each concept, and reporting honest held-out recall per concept, is the measured work the owner runs with the real model.
- **Elements are illustrative.** The legal-element rubrics are our plain-language reading of each provision, not a legal test.

## Scope note

Phase 5 widens the data the Guard reasons over. Phase 5b adds the vague-law classifier (a `DecisionBackend`) that answers the open legal questions — Art. 6(3) high-risk exception, Art. 22 solely-automated, Art. 50 transparency — on top of this wider detection.
